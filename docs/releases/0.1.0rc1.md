# SettleDiff 0.1.0rc1

This first release candidate packages SettleDiff for a recipient installation and
offline assurance trial. It is a prerelease, not a production-readiness claim.
Python 3.12/3.13 on macOS/Linux is the trial target. No PyPI publication, paid call,
production issuer signing or external outreach is included in preparing the draft.

The handoff includes a wheel, buildable source archive, hash-locked runtime
requirements, a synthetic signed example, standalone recipient instructions,
source/build metadata and SHA-256 checksums. The source archive contains package
code and build inputs; agent skills, experiments, local plans and private runtime
state are excluded. The full repository remains available for development tests.

Follow the [recipient guide](0.1.0rc1-recipient.md) after obtaining the example's
issuer fingerprint through a separate authenticated maintainer channel. The
temporary test issuer's private key is never serialized. The example demonstrates
`AUTHENTIC` issuance, content-tamper rejection, wrong/revoked key rejection, missing
signature failure and unchanged legacy integrity-only behavior. It contains no real
purchase evidence. The signature covers the example bundle, not release packages.

The existing deterministic financial checks, paid authorization/retry safety,
schema-4 report semantics and issuer envelope format are unchanged. Production
trust-anchor distribution, key custody and revocation remain operator duties.
Transparency logging, paid TLSNotary integration and ZK policy proofs remain deferred.

Before sharing, maintainers must complete the [release checklist](../development/release-checklist.md),
verify the exact uploaded file checksums and confirm that the draft points to the
tested source commit. A draft is not downloadable by an unaffiliated tester until
it is published or its files are explicitly handed over.
