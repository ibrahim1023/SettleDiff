# SettleDiff 0.1.0rc1: recipient trial

This release candidate tests installation and portable issuer authentication. It
is for macOS/Linux with Python 3.12 or 3.13. The example is entirely synthetic:
`VERIFIED` describes its fixture report, not a real purchase. No wallet, provider
account, model key or production issuer key is needed.

The candidate is initially a **draft release**, visible only to repository users
with the required access. A maintainer must publish it or explicitly arrange a
file handoff before an external tester can download it. No outreach is automatic.

## What to receive

Ask the maintainer for the complete handoff directory:

| File | Purpose |
|---|---|
| `settlediff-0.1.0rc1-py3-none-any.whl` | Installable Python package |
| `settlediff-0.1.0rc1.tar.gz` | Buildable package source, excluding development tools and private inputs |
| `requirements.txt` | Runtime versions and hashes exported from the committed lockfile |
| `settlediff-0.1.0rc1-synthetic-example.zip` | Synthetic bundles, detached signature, public test key and recipient check script |
| `RECIPIENT.md` | This guide, usable without the repository |
| `BUILD-INFO.json` | Source commit, candidate version and synthetic issuer fingerprint |
| `SHA256SUMS` | Checksums for the other six files |

Also obtain the **expected synthetic issuer fingerprint separately**, through an
authenticated maintainer channel. A fingerprint or key supplied only inside the
same download cannot establish independent trust. `BUILD-INFO.json` records build
claims; it is not a signed build attestation. Package checksums detect changed bytes
relative to a trusted checksum list; they do not authenticate the software publisher.
The example signature authenticates only its bundle, not the wheel or source archive.

## Check and install

Work in a new directory containing only those downloaded files. Check all checksums:

```bash
# Linux
sha256sum --check SHA256SUMS
# macOS alternative
shasum -a 256 -c SHA256SUMS
```

Use [uv](https://docs.astral.sh/uv/getting-started/installation/) to create an
isolated environment and install the locked runtime dependencies and local wheel:

```bash
uv venv --python 3.12 .recipient-venv
uv pip install --python .recipient-venv/bin/python --require-hashes --requirements requirements.txt
uv pip install --python .recipient-venv/bin/python --no-deps ./settlediff-0.1.0rc1-py3-none-any.whl
.recipient-venv/bin/settlediff --version
unzip settlediff-0.1.0rc1-synthetic-example.zip
```

The version must be `settlediff 0.1.0rc1`. Installing Python/dependencies may use
the network. Verification after installation needs no network or issuer database.
The archive contains no private test key; it was generated in memory and discarded.
The packaged public key is for inspection, not a replacement for a trusted pin.

## Authenticate the example

Read the fingerprint you obtained separately into a shell variable:

```bash
printf 'Paste the separately confirmed synthetic issuer fingerprint: '
read -r EXPECTED_ISSUER_FINGERPRINT
.recipient-venv/bin/settlediff verify-assurance synthetic-example/evidence/bundle.json \
  --signature synthetic-example/evidence/bundle.assurance.json \
  --issuer-fingerprint "$EXPECTED_ISSUER_FINGERPRINT"
```

Expected JSON: `status` is `AUTHENTIC`, `issuer_fingerprint` matches your pin, and
`machine_verdict` is `VERIFIED`. Exit status is zero. This proves that the pinned
test issuer signed the exact synthetic bundle and that existing bundle consistency
checks passed. It does not prove a real settlement, delivery, impartiality or freshness.

Run the seven automated recipient checks with the installed package:

```bash
.recipient-venv/bin/python -I synthetic-example/assurance_portability.py verify \
  synthetic-example/evidence --issuer-fingerprint "$EXPECTED_ISSUER_FINGERPRINT"
```

The script checks the original bundle, changed bytes, wrong and revoked issuers,
a missing signature, legacy integrity-only verification and rejected legacy
authentication. Every CLI subprocess blocks Python socket connection/DNS events,
uses a temporary working directory, and has a timeout and bounded output. This is
an accidental-network-use check, not an OS sandbox. A JSON map with seven expected
outcomes and exit zero means the trial passed. The bundled helper's `issue` mode
requires the repository fixtures and is not part of this recipient handoff.

To inspect tamper rejection directly:

```bash
cp synthetic-example/evidence/bundle.json tampered.bundle.json
printf ' ' >> tampered.bundle.json
.recipient-venv/bin/settlediff verify-assurance tampered.bundle.json \
  --signature synthetic-example/evidence/bundle.assurance.json \
  --issuer-fingerprint "$EXPECTED_ISSUER_FINGERPRINT"
```

Expected: `CONTENT_MISMATCH`, a null machine verdict, and exit status 2.
Stop if any check fails; do not substitute a key or fingerprint from the failed
download to make it pass.

## Report the trial

Return the candidate version, source commit from `BUILD-INFO.json`, OS/Python
version, checksum result, installation result and the seven-case JSON summary.
Include the exact command and bounded error output for any failure. Send no private
keys, passphrases, wallet data, credentials or customer evidence. The maintainer
will choose the feedback channel; this guide does not send anything automatically.

The package source archive is sufficient to rebuild the wheel. The full test and
fixture repository is at [SettleDiff](https://github.com/ibrahim1023/SettleDiff);
use the commit recorded in `BUILD-INFO.json` for a matching checkout. That full
repository is needed for the normal development test suite.
